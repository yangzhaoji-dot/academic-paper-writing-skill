# Procedure: Module planning

Goal: map the Reader Path and global narrative into local rhetorical functions.

## Inputs

Use:

- Paper Core;
- Reader Path;
- selected Narrative;
- Claim Graph.

The Reader Path should normally dominate local ordering. The Narrative retains the global argument, while modules provide reusable rhetorical functions.

## Rules

- A module is a function, not a paragraph.
- Select only modules needed by the Reader Path and narrative.
- Each module must name the claims it serves.
- Several Reader Path steps may be realized by one module or paragraph.
- One Reader Path step may require several modules when technical detail is necessary.
- Neighboring modules may be merged during discourse composition.
- A module may be omitted when its information is already established and repeating it would add no new role.
- Do not add a module merely to expose an internal framing label.

## Introduction planning

Choose from `modules/introduction/`.

A typical internal sequence may still include:

```text
context
-> existing-paradigm
-> limitation
-> consequence
-> core-insight
-> method-overview
-> evidence-preview
-> contributions
```

But the final module selection should answer the Reader Path, not preserve template symmetry.

For example, one concrete ambiguity may simultaneously realize context, consequence, and limitation. Do not split it into three paragraphs solely because three modules exist.

The actual sequence should follow reader dependencies, not a fixed template.
